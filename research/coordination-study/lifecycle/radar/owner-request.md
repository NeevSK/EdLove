# Owner request

The owner selected the next feature: a multidimensional radar of oneself or others for
each user, and indicated that existing scaffolding and documentation should be recovered.
This paraphrase preserves that request without selecting dimensions, scoring rules,
observation authorship, visibility rules or a platform priority that the owner did not state.

# Discovery boundary

Use the actual feature lifecycle: recover sources, distinguish the existing constructs,
publish sourced analysis and proposed requirements/invariants, review handoffs and retain
unresolved decisions. Do not treat a sample chart, declared FlowDAG, historical migration,
unverified catalog binding or a tool's availability as working end-to-end behavior.

Existing self-growth, teacher-student potential, teacher vitality and teacher-profile
research may have different purposes and authority. Preserve their scope and history.
Newer or more detailed text does not automatically supersede the other constructs.

The current API foundation/admission rules, frozen legacy/direct-data paths, UI boundaries,
privacy constraints and Deletion Veto remain applicable. Shared chart mechanics can be
specified and tested with synthetic data without admitting product measures or access rules.

The owner clarified: **"Shared experience; distinct measures and perspectives."**
This authorizes the shared-experience direction while preserving domain measure definitions
and separately attributed self/other perspectives. It does not select universal axes,
combine ratings, or grant new cross-person visibility and editing authority.
