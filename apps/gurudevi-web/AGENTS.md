# Gurudevi web rules

- The app is Vite + React + TanStack Router (`spa/`), built once per host: `pnpm build:sanctuary`, `pnpm build:explore` (`pnpm dev` / `pnpm dev:explore` locally). Each build is static files for Cloudflare Pages (`.github/workflows/gurudevi-web-deploy.yml`); there is no web server of our own. Server work goes to the v1 API (`apps/sanctuary-api`).
- Security headers (CSP, framing, HSTS) are defined once in `lib/security/responseHeaders.ts`; each build writes them to `_headers` with the app-link files and `robots.txt`. Explore's CSP allows no connection but its own origin. `node scripts/check-live-headers.mjs <url> explore|sanctuary` checks a deployment.
- This app is Gurudevi itself: `sanctuary.gurudevi.app` (signed in) and `explore.gurudevi.app` (no account, local sample data, never the backend). The public site `gurudevi.app` is `apps/gurudevi-public` (Astro).
- **Explore and sanctuary are one app.** Routes and screens never check which surface they are on: read `useSession()` (`spa/surface/session.tsx`) and query through the surface's `sources` (`spa/surface/sources.ts`). A new kind of data gets a `Source` with an Explore answer and an API answer. `check-web-stack` counts surface branches and the count only goes down.
- **Routes** are files in `spa/routes` ([decision](../../docs/decisions/2026-11-12-web-stack-astro-vite.md)); links are typed against them, so a link to a missing page fails the type check. Copy `spa/routes/_app/notifications.tsx` for a new place (`_app` mounts the shell and settles access; `_account` is sign-in and recovery; `_dev` is labs, local development only). Each route names itself with `head`. Screens get the surface's `sources` (queries) and `commands` (changes) from the router context. Workspace features and each capacity's floor come from `@repo/core/logic/places/workspaceCatalog` (model: `docs/architecture/places-roles-and-features.md`); the web only maps each feature to its route in `workspaceFeatureRegistry`, every menu lists `workspaceFeaturesFor(capacity)`, and `FloorGate` sends a link to another floor's feature to the person's own Workspace. Never show a page saying something is not for the person; send someone to an account step with `GoTo`, never `<Navigate>` (`spa/surface/navigation.tsx` says why). Public pages live in `apps/gurudevi-public` (Astro). `node scripts/check-web-stack.mjs` refuses any `next` import and Explore contacting the backend.
- In local development, sanctuary runs on `http://localhost:3000` and Explore on `http://localhost:3001` (`pnpm dev`, `pnpm dev:explore`). Screen tests render through `tests/support/render.tsx`, which puts the screen inside a router.
- Data reaches the app only through the v1 API. Never query the database from web code (`.from('table')`, `.rpc(`, storage, realtime): `node scripts/check-web-stack.mjs` counts them and the count only goes down.
- Build web UI with semantic HTML and browser-native behavior. Do not import React Native UI components or React Native Web into this app.
- Share only platform-neutral contracts, validation, repositories, the theme (`@repo/ui/theme`, `@repo/ui/theme/web`) and tokens with `gurudevi-mobile`. UI components come from `@repo/ui/components/web`.
- Design from the 360-430 px browser viewport upward. Desktop enhancement must not alter the primary phone journey.
- Every changed user journey needs browser evidence.
