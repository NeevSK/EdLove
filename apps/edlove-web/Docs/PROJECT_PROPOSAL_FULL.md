## I. PROJECT CONTEXT & RATIONALE

### 1.1 The Global Education Crisis

Education globally faces multiple interlocking crises:

#### Crisis of Imagination
Most people can only imagine one form of education: the industrial model they experienced. This **imagination poverty** prevents transformation even when people know the system is broken.

#### Crisis of Care
Education has been systematically reframed from **care work** (intimate, relational, human) to **industrial production** (standardized, measured, scaled). This reframing has:
- Devalued teachers as caregivers
- Reduced children to data points
- Prioritized metrics over human flourishing
- Created burnout and disillusionment

#### Crisis of Connection
Educational resources exist but don't flow to where they're needed. Knowledge exists but isn't accessible to practitioners. Communities form but remain fragmented. The ecosystem lacks **coherent connective tissue**.

#### Crisis of Context
Global solutions ignore local realities. "Best practices" from Finland are imposed on Sri Lanka without understanding systemic differences. The **local ground truth** is invisible or dismissed.

### 1.2 The Sri Lankan Specific Context

Sri Lanka's education system embodies these global crises with specific manifestations:

#### Official vs. Shadow Systems
- **Tuition culture** creates a parallel education system requiring family resources
- **Elite school hierarchy** produces massive equity gaps
- **Language medium** (English vs. Sinhala/Tamil) determines opportunity
- **Exam pressure** drives students and teachers toward performance over learning

#### Teacher Reality
- Teachers face immense systemic pressure with limited support
- Professional development is theoretical, not practical
- Teachers are evaluated on student exam performance
- No ecosystem thinking — each teacher is isolated

#### Resource Mismatches
- Schools need resources that exist in the system but can't access them
- Donors want to help but don't know where to direct resources
- No transparent coordination mechanism exists
- Bureaucracy creates barriers to direct support

### 1.3 Why Edlove Exists

Edlove is the response to these interlocking crises. It exists to:

1. **Expand consciousness** about what education could be (Domain I: Paradigm Cosmos)
2. **Reveal honest reality** of what education is (Domain II: Sri Lanka System)
3. **Provide practical tools** for teachers in the present system (Domain III: Gurudevi)
4. **Coordinate resources** transparently and effectively (Domain IV: Resource Ecosystem)
5. **Build community** for sustained collective change (Domain V: The Sangha)
6. **Establish intellectual foundation** for all of the above (Domain VI: Epistemic Core)

### 1.4 Why Now?

This moment in 2026 is uniquely positioned:

#### AI as Partner
Advanced AI (Claude, GPT-4) makes it possible to:
- Generate high-quality educational content at scale
- Build complex web experiences with minimal coding expertise
- Maintain living documentation that evolves
- Provide personalized experiences without armies of developers

#### Digital Infrastructure Maturity
Free/low-cost tools have matured:
- Static site generators (Astro) are production-ready
- Component frameworks (Svelte) are stable and powerful
- Hosting (Cloudflare Pages) is genuinely free at scale
- Content management can be done entirely in markdown/git

#### Post-Pandemic Consciousness
COVID-19 forced global recognition that:
- Education can happen outside traditional schools
- Technology can enable learning in new ways
- Care and connection matter more than metrics
- The system's fragility is undeniable

#### Sri Lankan Readiness
- High digital literacy and smartphone penetration
- Growing frustration with tuition culture pressure
- Teachers seeking alternatives and support
- Government openness to educational innovation

## IV. TECHNICAL ARCHITECTURE

### 4.1 Technology Stack

**Principles**:
1. AI-friendly (Cursor/Claude generate it well)
2. Free or near-free (sustainable without funding)
3. Fast and flexible (performs well, changes easily)

**Core Technologies**:
- **Frontend Framework**: Astro (static-first, zero JS by default)
- **Interactive Components**: Svelte (tiny bundle, compiles away)
- **Styling**: Tailwind CSS (utility-first, AI-perfect)
- **Animations**: GSAP (industry standard for scrollytelling)
- **Search**: Pagefind (static search, free)
- **Content**: Markdown + Frontmatter (Git-versioned)
- **Hosting**: Cloudflare Pages (free tier, global CDN)
- **Analytics**: Cloudflare Analytics (free) or Plausible ($9/mo)

**Total Monthly Cost**: ~$1.25/month (domain only) or ~$10.25/month (with Plausible)

### 4.2 File Structure Philosophy

Every file has a purpose. Nothing extra. Clean separation:
- `/src/pages/` — URL structure (file = route)
- `/src/content/` — All markdown content (typed with Zod schemas)
- `/src/components/` — Reusable UI (Astro + Svelte)
- `/src/layouts/` — Page-level templates
- `/src/styles/` — Global CSS and design system variables
- `/docs/` — This constellation of 11 documents

### 4.3 AI Workflow

**The Loop**:
1. Decide what to build (check ROADMAP)
2. Gather relevant docs for Cursor
3. Prompt Cursor with clear intent
4. Cursor generates code
5. Test locally (`npm run dev`)
6. Show Claude if something feels off
7. Claude helps debug/refine
8. Push to GitHub
9. Cloudflare auto-deploys
10. Repeat

**What to Feed Cursor**:
- Building pages: INDEX + DESIGN + TECH + Domain doc
- Building components: DESIGN (CSS variables + patterns)
- Writing content: PHILOSOPHY + DESIGN (voice) + Domain doc
- Fixing bugs: Specific file + TECH (for context)

### 4.4 Deployment Flow

**One-Time Setup**:
1. Create GitHub repository
2. Sign up for Cloudflare Pages
3. Connect repo to Cloudflare
4. Set build command: `npm run build`
5. Set output directory: `dist`
6. Point domain to Cloudflare
7. Done — every push auto-deploys

**Daily Development**:
```bash
npm run dev          # Local server at localhost:4321
# Make changes
git add .
git commit -m "..."
git push             # Auto-deploys in ~30 seconds
```

### 4.5 Performance Targets

- **Lighthouse Score**: 90+ across all categories
- **Page Load**: <2 seconds on 3G
- **Time to Interactive**: <3 seconds
- **Accessibility**: WCAG AA compliant minimum
- **Bundle Size**: <50KB JavaScript per page (most pages zero JS)

### 4.6 Content Schema

All content is typed with Zod schemas:
- `paradigmSchema` — Paradigm descriptions
- `thinkerSchema` — Thinker profiles
- `guideSchema` — Paradigm deep-dives
- `storySchema` — Field narratives
- `frameworkSchema` — Theoretical frameworks

This catches errors and makes AI generation consistent.

## V. DESIGN SYSTEM

### 5.1 Design Philosophy

**Not a website. An experience.**

Every visual choice is a philosophical statement. The aesthetic IS the message.

**Signature Tension**: Professional yet soulful and alive. Precise AND emotional. Structured AND breathing.

**Cinematic References** (The Protocol):
- Tree of Life (Terrence Malick) — Organic, cosmic, intimate
- Upstream Color — Dreamlike but grounded
- Columbus — Architectural precision holding emotion
- Duke of Burgundy / Taste of Things — Tactile, sensory warmth

### 5.2 Color Palette

**Primary (The Core)**:
- Deep Indigo `#2D3561` — Wisdom, depth
- Warm Gold `#D4A574` — Love, light (use sparingly)
- Soft White `#F5F1E8` — Space, breath (not pure white)

**Secondary (The Environment)**:
- Forest Green `#4A6357` — Grounding, nature
- Dawn Rose `#E8B4B8` — Tenderness, community
- Sky Blue `#A8C5D6` — Possibility, epistemic content

**Accents (The Sparks)**:
- Cosmic Purple `#9B7EBD` — Paradigm Cosmos
- Ember Orange `#E07A5F` — Gurudevi action
- Starlight Silver `#E8F4F8` — Subtle backgrounds

**Rules**:
- Never pure white or pure black
- WCAG AA contrast ratios minimum
- Gold is sacred — use for moments that matter
- Backgrounds breathe — generous space

### 5.3 Typography

**Type System**:
- **Display**: Cinzel (ceremonial, rare use)
- **Headings**: Libre Baskerville (dignified, literary)
- **Body**: Inter (clean, readable, modern)
- **Captions**: Inter italic (subtle metadata)
- **Code**: JetBrains Mono (technical content)

**Rules**:
- Body text never smaller than 15px
- Line length 55–75 characters
- Generous line height (1.7 for body)
- Paragraphs breathe (1.5–2× line height spacing)

### 5.4 Spacing System

Based on 8px base unit:
- `space-xs`: 4px
- `space-sm`: 8px
- `space-md`: 16px
- `space-lg`: 32px
- `space-xl`: 64px
- `space-2xl`: 128px
- `space-3xl`: 192px

**The Rule**: When in doubt, add MORE space. Edlove breathes.

### 5.5 The Aliveness Principle

**The site must feel alive.**

Not just beautiful. **Alive.** Like it's breathing. Like it responds to presence.

**What Aliveness Looks Like**:
- Subtle ambient motion (particles drifting)
- Responsive to scroll (gentle reactions)
- Texture and warmth (not flat)
- Unhurried pacing (contemplative)
- Optional ambient sound (always opt-in)
- Remembers returning visitors

**What It Is NOT**:
- Not flashy distractions
- Not auto-play video/sound
- Not infinite scroll traps
- Not pop-ups or aggressive CTAs
- Not gamification or manipulation

**Aliveness is the opposite of manipulation. It is the feeling of being in a space that cares.**

### 5.6 Voice and Tone

**Core Principles**:
- Tender but truthful (don't sugarcoat, but approach with compassion)
- Poetic but practical (beautiful language that's actionable)
- Inclusive (accessible to all, not just academics)
- Non-jargon default (explain complexity simply)
- Questions over statements (invite thinking)

**By Context**:
- Homepage: Warm, inviting, slightly poetic
- Paradigm Cosmos: Wonder and curiosity
- Sri Lanka: Honest, clear, respectful
- Gurudevi: Practical, warm, teacher-centric
- Library: Thoughtful, deep, accessible
- Resources: Helpful, clear, action-oriented
- Community: Human, warm, open

## VIII. RISK ANALYSIS & MITIGATION

### 8.1 Technical Risks

**Risk: Platform complexity becomes unmanageable**
- Mitigation: Keep stack simple. Astro + Svelte + Tailwind only.
- Mitigation: AI assistance (Cursor/Claude) for ongoing development.
- Mitigation: Comprehensive documentation maintained.

**Risk: Hosting costs explode with scale**
- Mitigation: Cloudflare Pages free tier handles 500k requests/month.
- Mitigation: Static site = minimal server costs.
- Mitigation: Only add paid services when absolutely necessary.

**Risk: Site performance degrades**
- Mitigation: Zero JS by default. Only add where needed.
- Mitigation: Regular Lighthouse audits.
- Mitigation: Image optimization and lazy loading.

### 8.2 Content Risks

**Risk: Content quality inconsistent**
- Mitigation: Claude AI generates all content following voice guidelines.
- Mitigation: Neev reviews every piece before publication.
- Mitigation: Community feedback loop for continuous improvement.

**Risk: Misinformation or inaccuracy**
- Mitigation: All research sourced and attributed.
- Mitigation: Domain VI frameworks clearly labeled (theory vs. practice).
- Mitigation: Stories clearly labeled (real vs. composite).
- Mitigation: Corrections published transparently when errors found.

**Risk: Cultural appropriation (especially Indigenous content)**
- Mitigation: Indigenous paradigm written BY indigenous voices, not about them.
- Mitigation: Compensation for indigenous contributors.
- Mitigation: Review by indigenous educators before publication.

### 8.3 Community Risks

**Risk: Toxic community dynamics**
- Mitigation: Clear community principles from day one.
- Mitigation: Active moderation (Neev + volunteers).
- Mitigation: Zero tolerance for harassment, gatekeeping, shame.
- Mitigation: Conflict resolution protocols established early.

**Risk: Community outgrows capacity to moderate**
- Mitigation: Start small (Discord, manageable size).
- Mitigation: Recruit volunteer moderators from trusted members.
- Mitigation: Eventually hire community manager if funding allows.

**Risk: Community expectations exceed capacity**
- Mitigation: Clear communication about what's possible when.
- Mitigation: "This is v0.1" or "v1.0" labeling shows development stage.
- Mitigation: Invite community to co-create, not just consume.

### 8.4 Resource Coordination Risks

**Risk: Resources mismatched or wasted**
- Mitigation: Start manual (Google Forms + personal review).
- Mitigation: Transparent reporting of every match made.
- Mitigation: Feedback loop with both donors and recipients.
- Mitigation: Only scale when manual process proves effective.

**Risk: Donors expect control or recognition**
- Mitigation: Clear upfront: edlove coordinates but doesn't control.
- Mitigation: Recognition is optional, not required.
- Mitigation: No naming rights, no preferential treatment.

**Risk: Recipients aren't actually helped**
- Mitigation: Follow-up on every match to verify impact.
- Mitigation: Adjust coordination based on what actually works.
- Mitigation: Honest reporting of failures, not just successes.

### 8.5 Sustainability Risks

**Risk: Funding insufficient to sustain**
- Mitigation: Costs kept below $1,000/year in Phase 1.
- Mitigation: Multiple revenue streams, not one source.
- Mitigation: Core platform can run indefinitely on minimal funding.
- Mitigation: If funding disappears, site remains as static archive.

**Risk: Neev burnout**
- Mitigation: Work is AI-assisted, not solo from scratch.
- Mitigation: Build community of co-contributors early.
- Mitigation: "One meaningful thing per week" pace, not everything at once.
- Mitigation: Grant funding eventually supports part-time coordinator.

**Risk: Loss of vision/mission drift**
- Mitigation: 01_PHILOSOPHY document is constitution.
- Mitigation: Nine topological invariants cannot change.
- Mitigation: Guiding questions filter all decisions.
- Mitigation: Annual review checks alignment with founding principles.

### 8.6 Political & Social Risks

**Risk: Government or institutional resistance**
- Mitigation: Not attacking the system, revealing it honestly.
- Mitigation: Gurudevi helps teachers WITHIN the present system.
- Mitigation: Domain II tone is respectful, not accusatory.
- Mitigation: Position as resource, not threat.

**Risk: Perceived as Western-centric despite intentions**
- Mitigation: Domain II is deeply Sri Lankan-specific.
- Mitigation: Indigenous paradigm BY indigenous voices.
- Mitigation: Gurudevi addresses local realities, not imported solutions.
- Mitigation: Content explicitly addresses global/local tensions.

**Risk: Seen as elitist or inaccessible**
- Mitigation: Free forever, no paywalls.
- Mitigation: Voice is poetic but accessible (not academic jargon).
- Mitigation: Mobile-first design (smartphones more accessible than computers).
- Mitigation: Eventually available in Sinhala and Tamil, not just English.
