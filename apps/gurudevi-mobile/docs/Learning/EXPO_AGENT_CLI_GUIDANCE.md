# Expo Agent CLI Guidance & Operational Playbook

> **The definitive operational reference for using `@expo/agent-cli` in Polymath Platform (`apps/gurudevi-mobile`) on Expo SDK 58.**
> **READ BEFORE RUNNING AGENT SETUP COMMANDS.**

---

## 1. What is `@expo/agent-cli`?

`@expo/agent-cli` is an agent-native CLI wrapper on top of the Expo toolchain (**Expo CLI**, **EAS CLI**, and `expo-doctor`) introduced in **Expo SDK 58**. It provides structured, deterministic, and parseable interfaces specifically designed for autonomous AI coding agents (Claude Code, Antigravity, Cursor, Codex) to inspect, run, diagnose, and smoke-test Expo projects without human intervention.

### Core Problems It Solves
1. **Target Ambiguity**: Distinguishes between standard Expo Go sandboxes and Native Development Builds (`dev-build`), preventing agents from running incompatible native code on Expo Go.
2. **Interactive Friction**: Replaces ANSI-heavy, paginated, and interactive terminal prompts with machine-readable outputs and a strict `--json` contract.
3. **Runtime In-App Control**: Provides direct runtime evaluation, error inspection, and UI tapping via `testID` without third-party drivers like Appium.
4. **Skill Synchronization**: Automatically maps and links package-shipped agent skills (`skills/<pkg>/SKILL.md`) to `.agents/skills` or `.claude/skills`.

## 2. Critical Polymath Platform Guardrails

> 🚨 **MANDATORY RULES: NEVER VIOLATE THESE IN `apps/gurudevi-mobile`**

### Rule 1: NEVER run `agents:setup` without `--no-agents-md`
By default, `npx @expo/agent-cli agents:setup` attempts to rewrite `AGENTS.md` at the project root with generic Expo instructions.
In Polymath Platform, `AGENTS.md` is our sacred platform architecture and guardrails document.
* **Prohibited**: `npx @expo/agent-cli agents:setup --yes`
* **Required**: Always pass `--no-agents-md`:
  ```bash
  npx @expo/agent-cli agents:setup --yes --project --agent codex --no-agents-md --json
  ```

### Rule 2: NEVER run `install --fix` or blindly accept version downgrades
Rule 1 of `AGENTS.md` strictly forbids `expo install --fix`. The Polymath mobile app pins sacred new-architecture dependencies (`react-native-reanimated` 4.7.1, `react-native-skia` 3.0.2, `react-native-gesture-handler` 3.3.0, `react-native-mmkv` 4.3.2, etc.).
* **Prohibited**: `npx @expo/agent-cli install --fix`
* **Permitted**: `npx @expo/agent-cli status` or diagnostic inspection only.

### Rule 3: Native Android Builds MUST run in WSL 2
`@expo/agent-cli dev` or `run:android` attempts to build native code on the host machine.
In our Windows environment, building native Android directly on Windows triggers path limit crashes (`CMAKE_OBJECT_PATH_MAX`) and Ninja dirty-manifest loops.
* **Prohibited**: Triggering native compilation from Windows host CLI.
* **Required**: All native Android compilation must use the repository's WSL 2 scripts:
  ```powershell
  # Dev Debug APK (default):
  pnpm run build:android

  # Install Dev APK on connected device:
  pnpm run install:android
  ```

### Rule 4: Target must be pinned to `dev-build`
`apps/gurudevi-mobile` uses custom C++ Nitro modules and custom native plugins. It cannot run in Expo Go. The `package.json` must explicitly declare `target: "dev-build"`.

## 3. Configuration in `apps/gurudevi-mobile/package.json`

Add the following configuration block under the `"expo"` key in `apps/gurudevi-mobile/package.json`:

```json
{
  "expo": {
    "agent-cli": {
      "target": "dev-build",
      "buildBackend": "local",
      "android": {
        "buildBackend": "local"
      }
    }
  }
}
```

* `"target": "dev-build"`: Instructs the agent CLI that Expo Go is unsupported and that a development client binary is required.
* `"buildBackend": "local"`: Informs agents not to spend EAS credits unless explicitly flagged with `--eas`.

## 4. Key Commands Reference

All commands can be invoked on demand via `npx @expo/agent-cli@latest <command>`.

### A. Understanding the Project State

| Command | Purpose |
|---|---|
| `npx @expo/agent-cli status` | Compares native code changes with the last build. Reports whether JS hot-reload is sufficient or a native rebuild is required. |
| `npx @expo/agent-cli doctor` | Runs `expo-doctor` with normalized, machine-readable output. |
| `npx @expo/agent-cli inspect:build-log` | Parses build output to isolate the exact line causing a native build error. |
| `npx @expo/agent-cli inspect:config-plugins` | Analyzes and outputs native modifications generated by custom Expo config plugins. |

### B. Dev Server Management

| Command | Purpose |
|---|---|
| `npx @expo/agent-cli dev --detach` | Starts the Metro development server in the background and returns immediately. |
| `npx @expo/agent-cli dev:logs` | Streams output from the detached dev server. |
| `npx @expo/agent-cli dev:stop` | Stops the running project dev server. |

### C. In-App Verification & Autonomous Smoke Testing

| Command | Purpose |
|---|---|
| `npx @expo/agent-cli smoke` | Reloads the app onto code on disk, navigates to a designated route, and checks for crash loops or runtime exceptions. |
| `npx @expo/agent-cli navigate --path <route>` | Deep-links into a route in the running app on a booted device or emulator. |
| `npx @expo/agent-cli runtime:errors` | Collects JavaScript runtime errors captured during execution. |
| `npx @expo/agent-cli runtime:tree` | Dumps the active UI component hierarchy ready for interactions. |
| `npx @expo/agent-cli runtime:tap --testID <id>` | Taps an interactive component by its `testID`. |
| `npx @expo/agent-cli runtime:type --testID <id> --text "val"` | Types text into a form input identified by `testID`. |
| `npx @expo/agent-cli runtime:reload` | Triggers a live fast-refresh / reload from disk. |

### D. Package Skills Management

| Command | Purpose |
|---|---|
| `npx @expo/agent-cli skills:list` | Lists all skills bundled by installed npm modules. |
| `npx @expo/agent-cli skills:sync` | Synchronizes and junctions package skills into `.agents/skills`. |
| `npx @expo/agent-cli skills:show <pkg>` | Prints the `SKILL.md` for a given package. |

## 5. Telemetry & Environment Flags

`@expo/agent-cli` includes telemetry reporting to Expo's servers. To run completely offline or in private CI environments:

```powershell
$env:EXPO_NO_TELEMETRY = "1"
$env:EXPO_OFFLINE = "1"
```

## 6. Recommended Agent Workflow for Gurudevi Mobile

When an AI agent is working on a mobile feature or bug:
1. **Pre-check**: Run `npx @expo/agent-cli status` from `apps/gurudevi-mobile` to verify whether native code has changed.
2. **If native code changed**: Rebuild inside WSL 2 using `pnpm run build:android`, then install to device via `pnpm run install:android`.
3. **If JS/TS only changed**: Ensure Metro is running (`pnpm --filter gurudevi-mobile start`), perform code edit, and run `npx @expo/agent-cli runtime:reload`.
4. **Smoke verification**: Run `npx @expo/agent-cli runtime:errors` or `npx @expo/agent-cli smoke` to guarantee no unhandled exceptions.
