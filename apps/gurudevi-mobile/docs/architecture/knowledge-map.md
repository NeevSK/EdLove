# Gurudevi Platform: The Architectural & Intellectual Landscape

## Overview
This document serves as the cohesive "map" of the Gurudevi Platform. It bridges the gap between **Theory** (Software Engineering Domains) and **Practice** (The Tech Stack). 

The platform is built on the principle of a **"Zero-Legacy" Sovereign Architecture**, where business logic is protected from technological churn.

---

## 🏗️ 1. System Topology & Structural Design
**Domain:** Software Architecture
**The Goal:** Maintain a "Sovereign Core" that doesn't know it's running on a mobile phone or a web browser.

- **The Concept: Sovereign Core vs. Imperative Shell**
    - The **Core** (`packages/core/logic`) is the brain. It only contains domain rules.
    - The **Shell** (`apps/gurudevi-mobile`) is the body. It handles UI, GPS, Push Notifications, and API calls.
- **The Pattern: Hexagonal Architecture (Ports & Adapters)**
    - We use **Adapters** (`packages/core/api` and `runtimes`) to connect the Core to external tools like Supabase or Inngest.
- **The Implementation:**
    - **Turborepo**: Manages the monorepo boundaries.
    - **NPM Workspaces**: Ensures `@repo/*` packages are isolated.

---

## 📊 2. Information Modeling & Data Governance
**Domain:** Data Engineering
**The Goal:** Ensure that data types are unified from the Database shelf to the Mobile screen.

- **The Concept: Single Source of Truth (SSOT)**
    - A change in the schema should propagate everywhere automatically.
- **The Pattern: Schema-First Development**
    - We define our world in `.zmodel` files first.
- **The Implementation:**
    - **Zenstack**: The "Master Architect." It handles schema, validation, and security rules.
    - **Prisma**: The bridge to the Postgres hardware.
    - **Zod**: Autogenerated from Zenstack to provide runtime safety in the UI.

---

## 🔐 3. Security Engineering & Authorization
**Domain:** Security & Multi-Tenancy
**The Goal:** Enforce complex institutional hierarchies (School -> Principal -> Teacher -> Student) safely.

- **The Concept: Attribute-Based Access Control (ABAC)**
    - Access is based on *attributes* (Role, SchoolID, Authority) rather than just simple folders.
- **The Pattern: POA (Point of Authority) Enforcement**
    - Security is not checked "in the button." It is checked at the "Gate" (The Proxy).
- **The Implementation:**
    - **CASL**: The engine that evaluates "Can this user do this action?"
    - **POA Proxy**: A JavaScript Proxy that automatically intercepts API calls to verify authority.
    - **Zenstack Access Policies**: Row-Level Security (RLS) deep in the database.

---

## 📡 4. Communication Patterns & Distributed Systems
**Domain:** Event-Driven Architecture (EDA)
**The Goal:** Handle complex, asynchronous school workflows (like "Send report to Parent when Grade is finalized") without crashing the main app.

- **The Concept: Eventual Consistency & Idempotency**
    - Systems might take time to update, but they will always reach the same state.
- **The Pattern: Orchestrated Async Logic**
    - The Mobile app "emits" an event and forgets about it; a worker handles the heavy lifting.
- **The Implementation:**
    - **Inngest v4**: The event orchestrator.
    - **Event Bus Schemas**: Defined in `core`, keeping the events type-safe.

---

## 🎨 5. Frontend Engineering & Visual Language
**Domain:** UI/UX Engineering
**The Goal:** A premium, "Zero-Legacy" interface that feels native on both iOS and Android.

- **The Concept: Atomic Layout Primitives**
    - We do not use raw `View` or `Text`. We use owner-owned building blocks.
- **The Pattern: Utility-First Semantic Theming**
    - Styling is done via semantic classes (e.g., `text-textHeader`) so the whole app's mood can be changed in one file.
- **The Implementation:**
    - **NativeWind v4**: Tailwind CSS for React Native.
    - **@repo/ui**: A hardened library of layout primitives (Box, HStack, Center).

---

## 🛠️ 6. Maintenance & Platform Hygiene
**Domain:** DevOps & Developer Experience (DX)
**The Goal:** Keep the "Fog" away by automating code quality.

- **The Concept: Static Analysis & Hygiene Audits**
    - If the code drifts from the architecture, the tools should scream.
- **The Implementation:**
    - **Platform-MCP**: Custom internal tools for A11y, Color, and Dependency audits.
    - **Biome**: High-performance linting and formatting.

## 📖 Glossary for New Developers

| Term | Meaning |
| :--- | :--- |
| **Sovereign** | Code that is independent of external libraries/platforms. |
| **BFF** | Backend-for-Frontend. The layer that translates data for the UI. |
| **Zero-Legacy** | The standard of having no "old" or "messy" boilerplate; everything is modern. |
| **Fabric** | The React Native New Architecture (Concurrent rendering). |
| **Fabric-Ready** | A component that works with the new high-performance engine. |
