# PNPM 11.8.0 Minor Upgrades and Changes Report

This document reports the details of the pnpm upgrade from version `11.5.2` to `11.8.0`. It tracks the individual minor jumps (`11.6`, `11.7`, `11.8`) to capture security hardening, command-line additions, and performance updates applied to the Polymath Platform.

---

## Summary of Version Changes

### pnpm 11.6.0
* **Disabling `.npmrc` Interpolation (Security Hardening):** Environmental variables inside `${ENV_VAR}` placeholders are no longer parsed/expanded inside project-level `.npmrc` files. This prevents malicious packages in dependencies from hijacking system secrets. Environment-based auth must now use standard `npm_config_` environment variables instead.
* **Network Concurrency Optimization:** Boosted the default concurrent downloader settings from `min(64, ...)` to `min(96, ...)` to quicken dependency resolution on low-core development environments.
* **Installation Resiliency:** If the local `pnpm-lock.yaml` is absent but `node_modules` remains fully intact, `pnpm install` avoids triggering a fresh, full re-resolution process.

### pnpm 11.7.0
* **Frozen Stores:** Introduced the `--frozen-store` CLI option, allowing read-only package stores (e.g., in Nix builds, bind mounts, or read-only container layer filesystems) to bypass lock-writes by running the SQLite `index.db` in immutable mode.
* **Workspace Batch Publishing:** Added `pnpm publish --recursive --batch` to speed up deployment processes for large monorepos, uploading packages in a single batch request instead of spawning sequential HTTP connections.
* **Rust Resolver:** Continued experimental integration of *pacquet*, the Rust-written package manager and resolver.

### pnpm 11.8.0
* **Dry Run Support:** Native `--dry-run` parameter added to `pnpm install`. Runs the complete dependency resolution step and reports what installation/upgrade operations *would* be performed without committing modifications to disk.
* **Secure Version Bootstrapping:** When bootstrapping the version configured under `packageManager` in `package.json`, pnpm now strictly reads configurations from verified, trusted global/user `.npmrc` files and environment variables, bypassing local workspace overrides. Registry signatures are validated before executing the downloaded binary.

---

## Workspace Impact Analysis

* **`.npmrc` Status:** The workspace `.npmrc` remains reserved purely for local package hoisted definitions and contains no environment expansions, which makes the 11.6.0 expansion deprecation a non-issue.
* **Monorepo Integrity:** The monorepo has been verified and installs cleanly using the new `pnpm v11.8.0` engine.
