🔍 The 2026 Agent-Friendly Statechart Ecosystem: Myth vs. Substrate Reality

Installed (@statelyai/agent@1.1.6)

1. Stately Agent (`@statelyai/agent`)

The Claim: Constrains LLM loops within deterministic XState machines. The LLM cannot invent transitions; it can only propose an event, which the statechart validates or rejects.
Substrate Reality: Prevents illegal transitions, but does zero validation of event payload semantics or physical screen presentation. Without coupling to physical routes (`NAVIGATION_POLICY`), the UX remains disconnected from reality.
Analyzed / Bounded

2. Formal Spec Skills (pstack / TLA+ / TLC)

The Claim: Mathematical proof of zero deadlocks before writing code; finds unreachable screens and emits Mermaid counterexamples straight into agent context.
Substrate Reality: Indispensable for distributed consistency (e.g. SQLite outbox WAL transactions and auth handshakes). Too rigid and brittle for fluid mobile gesture physics, spring animations, and bottom sheet detents.
Installed (@xstate/graph@3.0.4)

3. Model-Based Testing (`@xstate/graph`)

The Claim: QA writes zero manual path tests; graph traverser tests 100% of statechart permutations and clicks automatically.
Substrate Reality: The graph traverser generates path combinations, but cannot generate assertions out of thin air. It requires concrete Vitest/Playwright test harnesses wired to real DOM/Native elements.

Two-Layer Harmonization: Intent vs. Presentation Physics

Systems that treat specification and implementation as identical break because real user experiences have physical presentation constraints (bottom sheet detents, modals, layout breakpoints, offline states). Harmonization reconciles them without forcing false equivalences.

📋 Layer 1: Intent & Assurance (Product / BA / QA)

Declarative truth of what should exist. Written in PJC YAML, OpenAPI/OpenSpec, and Gherkin features. High-level, human-readable, and business-focused.

  • Format: packages/core/src/flows/pjc/*.yaml
    Captures user journeys, roles, step purposes, and business preconditions.
  • Purpose Field: purpose: "take_attendance"
    Explains why the step exists regardless of how the screen renders.
  • Contract: OpenSpec delta proposals & Spectral OpenAPI linting.

📱 Layer 2: Execution & Physics (Dev / UI Eng / Runtime)

Physical truth of what actually happens on the screen. Written in TypeScript flows, navigation policies, gesture handlers, and route catalogs.

  • Format: *.flow.ts + navigationPolicy.ts
    Captures layout modes (compact, regular), sheet detents [0.5, 1.0], and transitions.
  • Navigation Operations: PUSH, REPLACE, SHEET, PANEL, MODAL.
    Determines physical screen motion based on device viewport.
  • Runtime Engine: navigator.ts resolving concrete routes against routeCatalog.generated.ts.

⚡ The Harmonization Seam in Action

How the monorepo verifies alignment between Layer 1 Intent and Layer 2 Execution:

1. PJC Validation (`scripts/pjc.ts check`): Verifies all 10 YAML modules conform to Zod hierarchy schema with valid steps and presentations.
2. Flow DAG Audit (`scripts/audit-flow-dag.mjs`): Verifies that every step in active flows resolves to a real route without deadlocks.
3. Master Spec Pipeline (`pnpm run audit:spec-pipeline`): Runs OpenSpec, PJC, LikeC4, Spectral, and Route Catalog checks in one single command.
